When an orchestrator session is lost (crash, expiration, model switch), the last 10 conversation turns from SQLite are injected as silent context into the new session via a 60s sendAndWait() call tagged '[System: Session recovered]'. This prevents the user from losing conversational context without requiring full session persistence. Conversation log is bounded to 200 entries, pruned every 50 inserts, with messages over 500 chars truncated.
