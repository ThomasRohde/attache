All messages (from Telegram, TUI, API) are processed one at a time through a serial queue. The SDK session is not thread-safe — concurrent sendAndWait() calls would corrupt state. Queue includes per-message callbacks for streaming response deltas back to the originating UI. Session creation is coalesced via a shared promise to prevent duplicate sessions from concurrent callers.
