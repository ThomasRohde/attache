Key gotchas with the worker system: (1) Workers auto-destroy after EACH send_to_worker call — you cannot do multi-turn interactions with a single worker. (2) Worker state is in-memory only — all workers are lost on daemon restart. Database stores session IDs but session state doesn't persist. (3) If a worker crashes before .finally() executes, the session may leak (~400MB). SDK timeout eventually reaps these. (4) Cancelled workers suppress their feedBackgroundResult callback — no notification to user.
