Real-time response streaming uses HTTP/1.1 Server-Sent Events, not WebSocket. SSE is simpler, works through corporate proxies, and the one-directional server→client flow fits the use case (messages submitted via separate POST /message). 20-second heartbeat pings keep connections alive. Each client gets a connectionId on subscribe which must be included in POST /message.
